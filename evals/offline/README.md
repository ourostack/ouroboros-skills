# Fixed offline evaluation contracts

This alpha slice connects the fixed-six CLI controller to the existing native subject-turn protocol, held-out diagnostics, canonical/private operations, independent reviewer policy, native grader and committed publisher. Native execution is currently held before acquisition or allocation callbacks: trusted checker assertions and exec-time route/artifact instrumentation are not implemented. `offline run` returns `NATIVE_QUALIFICATION_REQUIRED` with exit 3, twelve unstarted cells and no model attempt even when native acquisition callbacks are supplied. Static validity, source-only test transports and a compatible inventory are not native qualification or evaluation passes.

`executeHeldOutCheck` retains diagnostic commands but never admits their exits, CI markers or package stdout as trusted assertion completion. The maintained checker identity is compared against the frozen subject manifest, not another copy of the post-subject file. `canaryExecuted` is unresolved and `externalAssertionsComplete` remains false: a candidate can echo a marker, print the complete public matrix or exit before any API call. The same trust limit applies to an oracle importing candidate code in its own process. Every diagnostic observation is unavailable until actual trusted instrumentation outside the candidate process exists; there is no caller-supplied successful receipt, opt-in flag or callback that enables production admission.

The diagnostic launcher uses only Linux `/usr/bin/bwrap`, requiring a root-owned, non-setid, non-writable regular executable. It requests separate user, mount, PID, network, IPC and UTS namespaces, an unprivileged identity, capability removal, read-only runtime/source/checker mounts and only disposable checker work writable. PID namespace lifetime, unlike a process group, contains `setsid` and double-fork descendants. There is no direct host-child fallback on Darwin or when this capability is absent. This launcher has not been natively qualified here: neither its own exit nor untrusted stdout establishes successful namespace setup or complete descendant cleanup. Raw launcher results remain diagnostics with `nativeQualified: false`. Required native proof includes actual denied host/controller access, same-UID process-state protection, ignored-stdio/detached descendants, timeout/cancellation/overflow cleanup and complete namespace-owner exits.

## Commands

Run from the repository root with Node 22.23.2 or later:

```sh
node scripts/skill-evals.cjs offline help
node scripts/skill-evals.cjs offline validate --dataset evals/offline/cases/v2-alpha-v1/dataset.json --fixtures evals/offline/cases/v2-alpha-v1/fixture-manifest.json
node scripts/skill-evals.cjs offline compare --left /absolute/left/run-set.json --right /absolute/right/run-set.json
node scripts/skill-evals.cjs offline run --plan /absolute/plan.json --output /absolute/fresh-output-root
node scripts/skill-evals.cjs offline run --plan /absolute/plan.json --output /absolute/fresh-output-root --native-inputs /absolute/source-bound-native-inputs.mjs
node scripts/skill-evals.cjs offline qualify-runtime --plan /absolute/runtime-qualification.json --output /separate/authorized/fresh-output-root
```

The legacy `validate`, `fingerprint`, `verify` and synchronous library exports remain separate and SDK-free. Offline static commands also require no Copilot SDK installation or inference credentials. The filesystem mechanisms target POSIX filesystems; they are not an OS sandbox.

| Exit | Meaning |
| --- | --- |
| 0 | Static validation, a complete run without failure/inconclusive cells, complete compatible replay, or the labelled unscored runtime control. Consult the command's receipt, not the exit alone. |
| 1 | A complete run containing an admitted product failure. |
| 2 | A complete inconclusive run, or an incomplete/incompatible comparison. No winner is selected. |
| 3 | Unavailable native qualification or infrastructure/protocol failure, including a committed unavailable final cell in an otherwise complete inventory. |
| 4 | Invalid invocation, input or sealed-artifact contract. |

Errors from the executable entry point are JSON on stderr with `kind: "offline_error"` and an artifact reference or null. An undefined or invalid return from the offline entry point is an infrastructure error, not implicit success.

`validate` reports the raw dataset hash, case count, each fixture's subject/held-out/canonical-input file counts and `requiresAdmittedProducerBinding`. Its output always states `behavior: "unverified"` and `execution.assessment: "not_performed"`.

For the fixed Alpha dataset, `run` validates the exact dataset, fixture/checker hashes, candidate identity and complete twelve-cell matrix before checking native prerequisites. It snapshots the original plan and expected-cell bytes into a fresh owner-only output root, with an empty attempt journal, all twelve cells explicitly unstarted and a null-grade `producer-status.json`. A native hold returns that artifact root with exit 3; it does not invent model calls or attempted cells. A partial matrix, stale control, overlapping output or reused output root is rejected. These incomplete run sets can be consumed by `compare`, retaining twelve missing cells on each side.

`compare` verifies the referenced plan, exact expected-cell matrix, every journaled attempt and published receipt inventory. It retains failed, pending, unpublished and unstarted cells, rejects duplicated inputs and rejects receipts re-labelled against another plan. For Alpha it reopens each committed observation, checks raw references, replays the maintained deterministic checks, reconstructs the frozen rubric and replays the existing native grading evidence. Only complete compatible replay sets `scored: true`; missing evidence stays unavailable. There is no fresh model judgment, aggregate grade or selected winner. Non-Alpha comparison remains inventory-only.

### Source-bound native inputs

The optional module must be an exact raw-byte member of the plan's existing `tooling-source-manifest.json`, rooted beside the plan. It exports `nativeInputs`; it must be inert at import and must not acquire credentials, start a native process or send a prompt as an import side effect. All imported runtime, composition and callback code remains subject to the existing complete-source admission, not merely the entry module's hash. The programmatic CLI entry accepts the same object as its third argument. No plan, dataset or lifecycle schema is replaced.

`nativeInputs` requires `assertAllocation({plan, expected})`, `assertSourceAndRuntime({plan, expected})` and a `Map` named `cells` containing every frozen cell ID. Assertions must consume the actual externally owned allocation and qualification evidence, throwing when unavailable; a quota observation, test receipt or successful no-op is not sufficient. The maintained checker capability hold currently precedes both assertions and acquisition; supplying these functions cannot bypass it. Once implemented, the controller makes immutable plan/matrix copies and checks both assertions before acquisition. Each cell requires real `open`, `assertConfinement`, `createDeskCallbacks`, `withPermission` and `readCanonical` functions. Subject cells additionally require `subjectBeforeSend` and `reviewHandler`.

`open({cell, plan, fixture, turnIndex?, sessionId?, resume?})` returns owned live resources, not a case result: `close`, the existing `runTerminalProtocol` arguments in `protocol`, actual `subjectTurn` installation/context fields, canonical `task`, indexed `traceDirectories`, a disjoint `checkRoot`, and the existing grader arguments in `judge`. Deterministic cells instead need their live `session`, native `privateOperations` inputs and actual `legacy` operation. `close()` is mandatory before any use; for deterministic admission it returns the existing `{runId, receipt, readArtifact}` stopped-writer proof. Every reacquisition is independently confined and eventually closed, including exceptional paths.

The native subject may supply its genuinely acquired `CopilotClient` through `protocol.nativeClient`. The existing loop still owns start, session creation/resumption, permission handling, send, terminal observation and cleanup. `subjectBeforeSend` selects the observed installed agent and connects the native Desk before activation checks; ordinary turns resume, and the fixed review restart creates a new session identity. Complete source seals are checked while managed roots are still live, before their owner removes them. A reacquisition must discover and seal new managed paths rather than reuse removed roots.

The controller materializes the exact Git seed, uses the unchanged dataset prompts, performs a real native write/read/remove probe before a subject turn, and waits for verified writer exits before held-out execution. It retains canonical history across restart, appends the separately declared scope, feeds actual independent findings back to the sole builder, and grades only when all required deterministic evidence is available. The private controller exercises the actual recording switch, disabled legacy path, canonical-linked commitment, protected bytes, authority negatives, revision-checked correction/readback/deletion and unrelated-record preservation; it restores the original switch and cleans up only its own IDs. The private strata keep null model roles and zero model counters.

`createReviewHandler` consumes the installed review/runtime-policy exports and the actual initial-controller credential handoff. Its `stopped(request)` callback must acquire a verified writer hold and return the owning asynchronous release function. `assertConfinement({directory, target, entry, command, env})` must establish genuine OS reviewer separation before spawn; private directories and environment rewriting alone are not isolation. The actual review policy's existing `spawnFn` and `psFn` boundaries must be supplied through `runtime` by the admitted OS role owner; the handler forwards them rather than silently running a reviewer as the controller's identity. The handler really starts with its scoped binary path absent, restores the measured bytes to that same path, preserves failure/cleanup/output evidence, observes actual native reviewer events and invokes the installed admission policy. Findings are not clean approval. Writer holds are released on both success and failure, and release failure prevents a successful return. Repository-effective `.roborev.toml` is explicitly unsupported until a supported parser supplies its actual policy.

`tracedConnection` wraps the actual native invocation with metadata-only Linux `strace`; the acquisition owner must apply it before startup and qualify the privileged tracer separately from native writers. `readWriterTrace` requires raw per-process files, every owned root, complete descendant lineage and observed exits. Missing records, missing descendants and unsupported mapped/asynchronous writes refuse admission. Authority observations track descriptor opens, duplication, closure and fork/shared-descriptor relationships; initial descriptors 0-2 are the qualified SDK's stdio pipes. `sourceWrite` and `authorityWrite` now conservatively include attempted writable opens, denied mutations and zero-byte writes, not only final byte changes. All outside-fixture mutations and all Git metadata mutations are out of scope unless an actual authorized operation can be established. No blanket outside-root, `.git/index`, canonical-directory or probe-path exemption is accepted. A probe pathname alone is unresolved; a qualified operation-scoped authorization record is still required. Relative/unresolved mutation paths, unknown writable descriptors, socket writes, network attempts (successful or denied), and unknown syscalls remain unavailable, not clean negatives.

Archive provenance is verified from actual archive and committed source bytes, without extracting untrusted members into the controller. The maintained fixture's direct-string public export is supported, but matching committed broken bytes proves provenance, not behavior. Subject build/pack/install/consumer observations recognize only diagnostic candidates bound to the actual `execve` operand spelling; `/bin/echo` with npm/node argv is not a route. Even recognized paths and the two explicit inline matrix programs remain unavailable: this tracer does not bind executable/script bytes at exec time, cwd, per-exec exits or build/archive/install/consumer artifact transitions. `pipelineCandidates` is never the admitted `pipeline`. Approved-target names in argv likewise remain diagnostic candidates rather than proof that the target was executed.

The generic controller does not supply trusted out-of-process checker assertions, qualified checker namespace/descendant evidence, exec-time route/artifact binding, a corporate native acquisition module, a platform installer, paid allocation, independent reviewer OS confinement or a stopped-writer implementation. Those are actual implementation and route inputs, not administrative source pins or success envelopes. In particular, a top-level startup executable that closes its client cannot be imported as a live acquisition API. No Docker fallback, direct-provider route, model substitution or synthetic transport is admitted as native.

`qualify-runtime` is the fixed, unscored Docker/SDK control route, not an arbitrary shell-command interface. It consumes an explicitly available immutable Linux/amd64 image containing Node 22.23.2, CLI 1.0.84-1 and SDK 1.0.13. The [example plan](runtime-qualification.example.json) requires an authorized named account and the actual locally available image identity. The output parent must already exist and be separate from the plan root. The initial envelope binds every controller archive member, the host/bootstrap hashes and the predeclared ownership name before invoking the named provider. The validated plan is snapshotted before callbacks run. The credential remains in memory and travels separately from file members through the controller's private stdin. No host bind mount, automatic image pull, identity switch or default installation change is performed.

The fixed bootstrap resolves `node` through `/usr/bin/env` inside that immutable image rather than assuming a `/usr/local/bin/node` location. Headless authentication explicitly selects the existing `COPILOT_GITHUB_TOKEN` variable with the supported `--auth-token-env` option; auto-login stays disabled and `--secret-env-vars` stays enabled. The SDK is not given `gitHubToken`, so it does not rename the credential into another environment variable.

Before loading the CLI, a fixed Node preload drops groups and changes the already-executed process to UID/GID 65534, checks zero effective capabilities and `NoNewPrivs`, and closes its private transition record. Moving that change before exec is not equivalent: exec restores process dumpability. The fixed Node options also disable SIGUSR1 inspector activation. Runtime home/state/work directories belong to that unprivileged role; controller records remain private. Only the supervisor's required `SETUID`, `SETGID`, `CHOWN`, `KILL` and `DAC_OVERRIDE` capabilities are added, with no privileged container or host PID namespace.

After the real SDK connects and before a model request, a separate credential-free same-UID process attempts to open the owned CLI's environment and memory and to read its descriptor link. It does not read credential bytes. Missing targets, readable state, a different UID, possible privilege regain, timeouts or unverifiable raw capture refuse the control. The consumer verifies the retained probe bytes against an owned process identity, not a caller's `protected` boolean. These observations are not by themselves full subject-tool, MCP, held-out-data or composition qualification.

This command currently checks one narrowly labelled control: delivered execution success for a semantically failing report, with root-idle/history/raw-event and owned-exit evidence. Exit zero means that component's evidence was observed, not that the runtime or product was admitted; `qualified`, `scored` and `grade` remain false, false and null. Success/failure/correction/batch/cancellation contrasts, effective-model/effort qualification, subject process-state protection, installed composition and the actual independent-review route are still separate obligations. A constant successful JSON record without the matching SDK/schema/history/process records is refused. Provider failure, a timed-out pending container name, unavailable cleanup and capture/publication failures remain explicit non-success receipts.

Failed RPC delivery and truncated output retain complete, hash-verified observed root requests, their call IDs, schema dispatch and validator counts without a grade. Each JSONL byte record is decoded separately from the actually retained `stdout.raw`, so a broken UTF-8 tail or later capture failure cannot erase intact prior records or count unretained requests. `rawProtocolPrefix` identifies those retained bytes; derived SDK/schema files may be unavailable after a capture failure. `verified_observed_prefix` is not a completeness claim. Raw SDK records are SDK capture, not raw provider HTTP data. Decoded strings cannot substitute for raw transport buffers. Schema replay is deduplicated by actual event identity; conflicting payloads remain a capture failure. Callback records preserve their actual invocation session and whether the work window was still open.

An observed root `assistant.usage` content-filter flag or `content_filter` finish reason produces an explicit unavailable disposition and retained raw event references. A later report cannot turn that observation into a successful control or grade. Child filtering is not relabelled as root filtering; timeout, capture and cleanup failures keep their existing precedence. No automatic retry or account/filter workaround is performed.

The control waits for an observed root turn after its own dispatch and an interactive, non-aborted root idle. The pinned SDK declares `aborted` optional and true on cancellation; an omitted flag or explicit false is ordinary idle, while null, malformed values and true are not. Startup, child, other-mode and aborted idle events stay in the raw capture but do not end the work window. A child error is not relabelled as a root session error.

Every awaited SDK work phase checks the original work deadline before invocation and after resolution. Root-session and event-capture failures stay latched across pending phases, including null or undefined rejection reasons; resolving metadata after such a failure cannot dispatch a prompt. The original deadline keeps precedence after expiry. Closing the work window prevents delayed startup, metadata, send or history promises from resuming SDK operations or publication after cleanup. Unobserved pending startup receives a bounded force-stop and settlement wait within the cleanup budget; unsettled startup stays explicit and cannot establish verified cleanup.

Native capture checks the 48 MiB aggregate and 240-file budget before each new write, with a separate 16 MiB/single-file reserve for final failure metadata inside the publisher's 128 MiB/256-file limit. Owned cleanup commands remain bounded and continue after capture failure, but missing raw cleanup evidence remains unavailable and prevents a final commit marker. Timeout stays primary when cleanup or publication also fails. Transport children use a bounded hard-stop signal; that is not proof of the separate SDK/container process tree's exit.

### Independent native grading API

The maintained `runRuntimeQualification` export also accepts an `assessment` object with exactly `caseId`, `criteria`, `fixedVerdicts`, `evidenceRoot`, `evidenceIndex` and `evidenceSeal`. This executes the same fresh SDK loop, not a second provider or conversation implementation. `fixedVerdicts` contains `{criterion, verdict}` records from trusted deterministic checks; an empty array leaves all criteria to semantic evaluation. `evidenceSeal` contains the complete ordered `{path, sha256}` list, frozen before the judge starts. `prepareNativeAssessment` validates it against the existing confined reader.

The evidence archive is separately bounded to 16 MiB per file and 32 MiB total, validated before the first staging write and placed in the controller's private root. The unprivileged model process receives only the bounded reader and terminal reporter; it cannot browse the staged evidence, activate plugins or load another session's context. Each criterion must cite an indexed path, and a report cannot contradict a frozen deterministic verdict. Such a contradiction receives typed failure and may be corrected; all requests and handler entries remain counted.

Admission requires actual `session.start` and `assistant.usage` observations for the selected model, high reasoning effort and default context, together with the native raw events, history, private evidence seal and owned-runtime cleanup. Filtered, absent or conflicting effective configuration remains unavailable. The host replays the same report-admission owner against captured request, handler, completion, history and process records before publishing a grade. A valid product failure is successful native execution and yields the API's product-failure exit 1; pass is 0, inconclusive is 2 and unavailable/protocol/infrastructure is 3. Outer timeout, cleanup or publication failure removes any admitted grade while retaining observed attempts.

`runTerminalProtocol` accepts an optional native `AbortSignal`. Explicit cancellation interrupts even a pending send, invokes bounded owned cleanup and retains a run-bound cancellation observation; an SDK invocation's finally-abort is not this signal. A reached deadline and an already latched root failure retain their precedence. Late callbacks receive typed failure without reopening final admission. A terminal cancellation label without its actual scoped observation is refused on replay.

This grader API consumes retained evidence; it does not itself prove that an installed subject, independent reviewer, canonical-state producer or held-out checker produced that evidence. Those remain responsibilities of the six-case orchestration and its source-bound installation, not claims inferred from a grader's pass.

### Fixed native subject turn API

The same `runTerminalProtocol` loop accepts a separate `subjectTurn` instead of an assessment. Its exact fields are `schemaVersion: 1`, `caseId`, `turnIndex`, `sessionId`, `resume`, `actorRoot`, `canonicalRoot`, `person`, `taskRef`, `agent`, `pluginDirectories`, `mcpServers` and `sourceSeals`. Each source seal contains its absolute `root` and complete `{path, sha256}` file inventory. Source, canonical state and installed plugins require distinct direct roots. Case and turn select the unchanged dataset prompt; callers cannot supply replacement prompt text.

Subject execution uses native `copilot-cli` mode, explicit installed plugin directories and a selected file-based agent. It appends workspace context, not copied method instructions. Ordinary subsequent turns use the SDK's actual `resumeSession` API. The collector retains native tool, selected-agent, connected-MCP and invoked-skill responses; a selected name alone is insufficient. Actual agent bytes must belong to the sealed installation, and the native MCP host must report exactly one connected Desk client without unresolved connection/auth failure.

Unrestricted subagent, factory, scheduling and unrelated authority tools are excluded. Native built-in read/patch hooks confine direct filesystem access; additional tools go through their actual permission context rather than inheriting a blanket pre-tool approval. Managed human-only approval and sandbox bypass cannot be granted automatically. These controls supplement, but do not replace, the orchestration's required OS role isolation and process cleanup.

The trusted orchestration may supply `subjectBeforeSend` for real canonical operations through the already-created native SDK session and `reviewHandler` for the declared independent source-bound reviewer. They are module callbacks, not caller-supplied shell commands or serialized producer claims. Subject sessions have no grading tool. Their terminal is `subject-turn-finished`, with an observed/unavailable/bounded-stop disposition, null grade and retained evidence. Resumed configuration uses the actual hashed persisted start together with current SDK usage, explicitly distinguished from a new live start and from raw provider HTTP data.

This turn API is a component of the fixed controller. Its observations do not by themselves establish held-out checker execution, canonical history continuity, independent review admission, installed composition qualification or a scored case. The controller's actual native inputs and retained evidence must establish those facts separately.

These are public, fixed generic cases, not a statistical benchmark or unseen training data. Subject-visible baseline tests are not held out. The maintained-checker canary and installed-package omitted/positive/zero matrix have distinct expectations; a deliberately red capability oracle must remain red when mutation is forbidden. Do not turn every oracle into “repair to green,” substitute keyword checks, expand the rubric after seeing an outcome or rerun a valid failure for a better result.

Dataset and fixture version 1.0.1 correct the capability witness before scored use: the plausible sibling has a genuinely successful challenge, while the handoff names only the authorized target and does not disclose the sibling's oracle role. The exact authorized target still fails its held-out zero-value check without mutation. The six-case rubric is unchanged.

An Alpha run-set consumer requires all twelve cells: each subject case once with Astra and once with Opus 5, retaining the separately frozen judge configuration. The deterministic privacy case runs once for each configuration stratum, represented by repetitions 1 and 2 respectively, with null model roles and zero model-admission counters. These two executions are not invented model calls. A selected subset, extra repetition, substituted execution kind or missing model stratum is refused rather than reducing the denominator. Baseline and candidate together have twenty-four cells.

## Producer and role boundary

`materializeFixture` reads the frozen manifest twice without retaining all payload buffers, verifies raw hashes and source identity, creates fresh nonoverlapping actor/checker/canonical roots and seeds a real local Git repository with the configured author and committer. It has no remote or inherited hooks. Its actor view excludes held-out and canonical fixture input and removes `CONFIG_FILE`, `EVAL_SUBJECT_SNAPSHOT` and `CHECKER_CANARY_TOKEN`.

The native integration must enforce those views at the OS boundary, assign the actual role identities, demonstrate that the subject can write its intended workspace and keep controller/evidence roots inaccessible. It must not place the complete fixture source tree or held-out payload in the actor-readable installation. Privileged checker inputs and canary injection belong to checks after the actor and its writers have stopped. Directory policy tests alone do not prove isolation.

`executeHeldOutCheck` in `check-executor.mjs` now executes the frozen local command checks rather than accepting supplied command results. Its input is `{fixtureId, checkId, actorRoot, checkerRoot, workRoot, output, stopped, limits, signal}`: `output` is the existing `openRunOutput` owner; `stopped` contains the existing `{runId, receipt, readArtifact}` cleanup evidence; `limits` and the optional cancellation signal use `captureBoundedCommand`. It verifies stopped-process references and held-out hashes, copies the stopped source into a fresh disjoint root, retains raw command/exit evidence and refuses changed original source, execution snapshots or held-out inputs. The maintained CI valid/invalid/canary routes, original tests, retry/quote/capability oracles and actual existing-archive external consumer execute without repacking or repairing the subject's deliverable. Canary replacement is confined to the disposable execution copy. Package installation is offline with lifecycle scripts disabled; the trusted caller checks all three returned public observations before recording external completion.

The fixed controller calls this executor after native cleanup and full writer-lineage observation. The executor itself always returns `admitted: false`, labels its execution owner as the held-out controller and leaves complete write/authority tracing unavailable. It does not manufacture the subject's challenge history, Git/archive provenance, review results or canonical/private state. Its received cleanup proof covers the declared observed processes, not an independently discovered complete writer lineage; `captureBoundedCommand` likewise covers its direct child, not a whole sandbox. The controller must establish OS isolation and complete writer ownership, combine actual evidence, then use the existing grader and publisher. A command component passing here is neither native qualification nor a completed six-case run.

The review/rework and protected-recording cases require real admitted producers. An absent reviewer or recording route is unavailable, never a passing mock. The native path must exercise actual source-bound review, repair and re-review. Reviewer credentials must be supplied explicitly for that phase; ambient host/keychain discovery is not a credential route. Copilot CLI's `--secret-env-vars` strips listed values from shell and MCP environments, so hiding a token that way does not automatically authenticate a reviewer child.

An explicitly authorized named `gh auth token --hostname <host> --user <account>` provider may be invoked at the trusted controller's initial launch boundary, before any subject starts. Clear `GH_TOKEN` and `GITHUB_TOKEN` for that provider call, keep its result in memory and pass it only to the phase-scoped child/callback environment. This is not account discovery, cache copying, subject-side secret recovery or permission to disable stripping. Provider failure remains a failed attempt; credential values and hashes never belong in artifacts.

Native source/agent activation, both-model terminal success/failure/correction/batch/cancellation behavior, the outer startup/send/work deadline and complete owned-runtime cleanup remain qualification requirements. Only the real Copilot CLI/SDK with the pinned `gpt-6-astra` and `claude-opus-5` configurations is in scope. No direct provider API, replacement conversation loop or arbitrary caller-supplied shell runner is provided.

## Evidence and admission

`createEvidenceReader` uses maintained Gauntlet index validation followed by confined, single-link regular-file reads. It rejects symbolic/ancestor links, hard links, NUL-bearing or invalid UTF-8 text, changed seals and unindexed paths. It limits each file to 16 MiB and each page to 1–16000 UTF-16 code units. The opened descriptor must match the pre-open device/inode before any bytes are exposed; descriptors are nonblocking and checked again after reading. Raw-byte seals do not use the legacy BOM/CRLF-normalized `sourceFingerprint`.

`createReportAdmission` keeps complete root requests, partial/unobserved arguments, excluded child requests, schema observations, handler entries and delivered SDK completion references distinct. Call identity includes the observed root window; supported turn IDs are retained, and missing IDs stay null. Stable replays do not create another request. Conflicting payloads, ambiguous scope or incomplete coverage cannot admit a grade. Shared `reconcileJudgeHistory` checks the actual hashed history against every root attempt and supported window. The pinned SDK marks `session.idle` as ephemeral, so a live terminal explicitly carrying that marker need not appear in persisted history; the live raw terminal remains required and no event is inserted into history. Any historical terminal that does exist must agree in identity, mode and non-aborted state. Missing attempts, incomplete windows, a missing durable terminal or a contradictory historical abort stay unavailable. The pure admission, native loop and native control verifier use this same boundary.

The four counters are `observedRequests`, `schemaAcceptedHandlers`, `validatorAcceptedReports` and `admittedGrades`. They count their named, correlated observations, not unseen activity; unqualified handler scope cannot be counted as an accepted root handler. Raw records and scope ambiguity remain visible in the attempts. A successful handler return is not delivered RPC success. A semantic fail is a successful terminal tool result and, with complete evidence, becomes `product_failure`.

Exactly one validator-accepted terminal request can be admitted. Multiple valid reports invalidate the run instead of selecting the favorable one. Malformed requests receive typed execution failures and may be corrected before the deadline, with all attempts retained. Ordinary SDK per-invocation finally-abort is not run cancellation. A late report cannot rescue a timeout or cancellation.

The fixed rubric requires an actual failed criterion for overall fail and an unclear criterion for investigate. Extra-rubric observations remain `unexpectedConcerns` without changing the fixed score. Syntax and citation validation do not prove that a quotation or judgment is true. The pure admission API consumes collector verification decisions; passing synthetic booleans to it is not native qualification.

## Artifact and comparison contracts

`openRunOutput` creates a null-grade incomplete envelope before work. Raw stdout/stderr remain lossless and separate from decoded text views. All managed writes and appends enforce aggregate bytes/file count before allocation, reserving one file and bounded JSON space for an atomic failure annotation. Plans too small for that reserve fail before output creation. `writeArtifact` shares this accounting and refuses raw-stream and publisher-owned filenames. Stream overflow and write failures preserve available evidence and permanently prevent commit. A second disk failure cannot truncate the original envelope. Presentation files are not the outcome authority.

Semantic outcomes use `runContext.executionKind` from the frozen expected cell; a receipt cannot choose or override that route. A `deterministic` cell may publish `passed` or `product_failure` with `grade: null` and all four model counters zero. A `subject_with_judge` grade requires exactly one validator-accepted report. The committed reader rechecks those rules, and run-set validation requires the receipt's execution kind to match its expected cell. Ungraded infrastructure/control artifacts do not acquire a scoring route by inference.

Successful publication writes the receipt and file inventory, then atomically renames `COMMITTED.json` last. The reader verifies all named raw hashes, lengths and modes and rejects missing, changed, linked or extra files. Inventory traversal retains metadata rather than all payload buffers and checks file count and aggregate bytes before reading another file. Limits include 4096 files, 8192 directory entries, depth 64, 16 MiB per file and at most the frozen 1 GiB aggregate ceiling. JSON artifacts are bounded to depth 64 and 100000 values.

`captureBoundedCommand` accepts an executable, argv and explicit environment, never a shell command string. It retains raw stream prefixes, separates timeout/cancellation/infrastructure outcomes and bounds direct-child cleanup. Its process observations cover only that captured direct child; they are not the SDK's complete owned-runtime cleanup proof. `validateCleanupReceipt` requires run-bound, hashed spawn and exit observations, not a boolean or PID alone.

The [schemas](schemas/) freeze plans, expected cells, run sets, journals and schema events. Journal hashes bind compact `JSON.stringify(record)` bytes plus one newline per record; do not reformat a retained journal. The inventory-only library helper is not a native grade validator.

Candidate comparisons require the same dataset, checks, admission/tooling/runtime/binding/limit configuration and complete subject **and** judge configurations. Method comparison additionally requires matching non-method source and actual source/method partitions. The CLI reads `source-manifest.json`, `non-method-source-manifest.json` and the plan's method-manifest reference from each run-set root. Each manifest is `{schemaVersion: 1, files: [{path, mode, bytes, sha256}]}` over raw source bytes. Model-ranking dimensions are unsupported in alpha, even when both families qualify in separate cells.

Offline receipts may be linked by reference to an existing work record. This evaluator creates no online work item, measurement database, price conversion or transcript import. A protected work store is never an evidence root.
